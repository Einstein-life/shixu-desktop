# 科研项目、分析流程与结果记录改进

更新：2026-10-20。

## 产品方向

科研人员最需要的是在几周或几个月后仍能回答：为什么做这项分析、使用了什么样本与版本、当前结论由哪份结果支持、哪里存在不确定性、下一步该做什么。

核心工作区围绕“研究问题 → 分析流程 → 结果证据 → 结论 → 下一步”组织内容。研究设计与可复现性信息按需展开。今日调度负责执行，项目负责长期研究记录，同一份记录可以用于组会、申请书和论文方法整理，减少重复录入。

## 五段式记录与实验结果关联

1. 打开“项目进度 → 分析与结果”，填写研究问题，选择或编辑分析流程。
2. 在“实验执行 → 记录结果”中选择关联项目，填写结果、偏差以及原始文件/链接（每行一条），点击“保存结果”。更新结果不会重置该实验的计时和步骤进度。
3. 返回项目“分析与结果 → 结果证据”，查看自动汇集的实验结果、样本/批次、步骤进度和文件引用。也可在“选择补充关联的实验”中引用其他项目的实验，不改变其原项目。勾选后点“刷新证据来源”即可用于当前草稿。
4. 在“结论”中分别添加结果结论、局限或相反证据；为每条记录勾选相关分析步骤、项目文件、实验结果和实验文件。项目阶段性解释独立保存，实验结果更新不会改写研究者的结论。
5. 在“下一步”中记录待验证、补做实验或继续分析的行动，设置状态，并可生成今日事项。同一行动已有未完成事项时不会重复创建；行动状态与任务完成状态分别维护。

实验卡片的“在项目中查看分析与结果”可直接打开关联项目；项目中的“查看 / 编辑实验记录”会先保存当前研究记录，再打开对应实验的结果编辑器。项目卡片展示实验证据、结论数量和未完成的下一步行动。

项目记录和研究方案草稿按这五段导出 Markdown；周报复用研究问题、分析进度、最新实验证据、结论、局限及行动记录。研究方案仍需研究者审核和补齐，可作为申请书整理材料的起点。

这些关联读取原始实验的最新记录，不是冻结的历史版本。删除实验、移除文件或解除关联后，已保存结论里的来源引用仍保留并提示复核。引用文件只保存路径，JSON/Markdown 不包含文件内容；分享或备份原始文件需另行处理。实验结果和进度记录均不自动代表通过质控或证明科学假设。

## 本次已实现

1. **项目内嵌分析流程。** 新建或编辑项目时可以选择流程；已有项目点击“分析与结果”进入工作区。可追加其他流程，保留原步骤，支持修改、删除和增加自定义步骤。
2. **逐步记录。** 每步包含名称、未开始/进行中/已完成/受阻状态、预期产出、方法与质控检查点、本次结果/偏差/决策依据及最近编辑时间。完成状态只表示工作进度，质控和科学结论由研究者记录。
3. **可复现性记录。** 保存研究问题、设计与主要比较、输入数据和样本表、参考基因组/注释/数据库版本、软件环境、参数/脚本/作业号、结论与局限。
4. **关联结果。** 支持手填路径、网页链接、服务器路径；桌面端可选择本机文件和目录。每项可命名、关联分析步骤、填写版本与结论说明。本机文件在文件管理器中定位，网页在默认浏览器打开，服务器路径可复制到分析环境。
5. **连接今日任务。** 分析步骤可生成关联项目的今日分析事项，同一步骤已有未完成事项时避免重复创建。运行中的程序可以沿用调度页的“提交等待”功能。
6. **复用已有记录。** 项目页和归档回看提供工作区入口；周报包含进行中项目的分析进度、阶段结论及结果引用；支持导出完整项目记录和研究方案草稿 Markdown。
7. **双语与兼容。** 新界面支持中英文；旧项目自动补齐空的研究字段，原有里程碑和总结保留。用户自己输入的记录不会因切换语言而改写。

### 分析流程覆盖

| 流程 | 关键内容 | 对应参考资源 |
| --- | --- | --- |
| Bulk RNA-seq | 设计、原始质控、比对/定量、样本关系、差异表达、功能解释 | [nf-core/rnaseq](https://github.com/nf-core/rnaseq) |
| 单细胞 RNA-seq | 细胞质控、双细胞、整合聚类、注释、样本层面比较 | [nf-core/scrnaseq](https://github.com/nf-core/scrnaseq) |
| ATAC-seq | TSS/片段与复杂度评估、峰集、差异可及性、motif | [nf-core/atacseq](https://github.com/nf-core/atacseq) |
| ChIP-seq / CUT&Tag | 对照与背景、峰模型、一致性、差异富集 | [nf-core/chipseq](https://github.com/nf-core/chipseq)；CUT&Tag 参数需单独验证 |
| WGBS / RRBS | 转换率与 M-bias、覆盖过滤、DMC/DMR、表达联合 | [nf-core/methylseq](https://github.com/nf-core/methylseq) |
| WGS / WES | 覆盖与身份、胚系/体细胞策略、变异注释、验证 | [nf-core/sarek](https://github.com/nf-core/sarek) |
| small RNA / miRNA | 接头与长度、分层注释、多重比对、差异与靶标 | [nf-core/smrnaseq](https://github.com/nf-core/smrnaseq) |
| 16S / ITS | 引物与去噪、ASV、分类和多样性、组成性统计 | [nf-core/ampliseq](https://github.com/nf-core/ampliseq) |
| 宏基因组 | 宿主过滤、物种/功能概览、可选组装分箱、比较分析 | [nf-core/mag](https://github.com/nf-core/mag)；不同目标需选择不同工具 |
| 定量蛋白组 | DDA/DIA、鉴定 FDR、缺失值、差异蛋白与验证 | [nf-core/quantms](https://github.com/nf-core/quantms) |
| 代谢组 | 峰表、空白与混合 QC、漂移、差异及鉴定等级 | [xcms](https://github.com/sneumann/xcms) |
| 多组学 | 样本/特征统一、整合与稳定性、机制证据和验证 | [MOFA2](https://github.com/bioFAM/MOFA2) |

以上链接是进一步选择方法的参考资源。应用中的内容是人工整理的设计和记录模板，不是这些仓库的可执行封装，也不表示一个仓库覆盖整条下游分析链。模板没有自动下载、安装或运行这些工具。

### 一个使用例子

建立“处理对基因表达的影响”项目 → 选择 Bulk RNA-seq → 填入比较、批次和生物学重复设计 → 将样本表和 MultiQC 报告关联到对应步骤 → 在样本关系步骤记录离群样本与排除理由 → 记录设计公式、软件和参考版本 → 保存差异结果表、PCA 图、分析脚本及阶段结论 → 导出研究方案草稿或项目记录。

研究方案草稿包含研究问题、设计与数据、技术路线、预期产出、质控和风险检查、前期结果、可复现性信息及里程碑计划。缺失内容标记“待补充”；不会凭空补写结果、预算或可行性结论。

## 后续建议与优先级

| 优先级 | 改进 | 为什么对科研记录有帮助 | 建议验收方式 |
| --- | --- | --- | --- |
| P0 | 全局搜索与筛选 | 按基因、样本号、文件名、项目、结论和标签查旧结果，减少翻目录 | 输入已知关键词能找到项目、步骤、结果与所在路径 |
| P0 | 分析运行版本 | 同一流程保留 run 1/run 2，比较参数、参考和结论差异，避免重跑覆盖 | 重跑保留旧记录，能够指定论文使用的最终版本 |
| P0 | 最小记录与渐进展开 | 默认只需标题、一步和一条记录；高级参数按需展开，减少使用负担 | 新建常规项目无需填满全部研究字段 |
| P0 | 样本表关联与校验 | 将湿实验样本、测序编号、分析分组和最终图表连接，防止错配 | 能识别重复样本号、缺失分组、批次混杂提示与参考版本不一致 |
| P1 | 证据版本与复核标记 | 当前已支持结论关联多个分析、文件及实验；后续增加冻结版本、证据强度和复核状态 | 能指明论文采用的证据版本，并保留后续更新差异 |
| P1 | 文件迁移与完整性 | 检测关联文件失效，支持项目根目录整体重定位及按需校验哈希 | 移动项目目录后可一次修复路径，不修改分析记录 |
| P1 | 日期化研究日志 | 用“发现—问题—决策—下一步”快速记一条，每次会议留决定与负责人 | 周报只汇总本周新增或更新记录，能追溯结论变化 |
| P1 | 图表与报告预览 | 内嵌只读图片/PDF/表格预览，查看结果不必频繁切换软件 | 大文件分页读取；本地 HTML 与脚本不作为可信应用代码运行 |
| P1 | 可携带的项目归档 | 按用户选择打包脚本、关键结果和清单，区分“仅记录”与“包含文件” | 换一台机器可以恢复项目索引并查看选择打包的文件 |
| P2 | 分析环境集成 | 按需导入 Nextflow/Snakemake/MultiQC 的运行摘要，减少手工录入 | 导入来源、版本和状态明确；失败/取消/人工复核可区分 |
| P2 | 协作与交接 | 明确负责人、等待对象、交付物与签收记录 | 合作者能读懂项目包，敏感数据共享范围由用户决定 |

建议先实现搜索、运行版本和样本关联，再考虑远程执行和多人协作。前者直接解决“找不到、记不清、对不上”；远程执行还涉及计算资源、环境、认证和调度系统，适合作为后续独立模块。

## 当前边界

- 文件是引用，导出的 JSON/Markdown 不携带文件内容；路径移动或换机器后需更新。
- 分析流程目前用于计划和记录，不自动执行分析、不实时读取服务器作业状态。
- 版本与参数是人工录入，尚未自动捕获环境、校验文件哈希或生成不可篡改审计记录。
- 同一步骤生成任务后，任务和步骤的完成状态分别维护，避免将程序结束等同于分析复核完成。
- 周报当前列出进行中项目的结果引用，尚未按“本周新增结果”筛选。
- 自动保存、研究草稿跨重启恢复、多个分析运行的对比和全局检索仍属于后续工作。

## 建议的使用体验指标

关注首次建立项目时间、每周记录次数、结果检索成功率、从旧结果定位到脚本/参数的用时、组会材料整理耗时。通过实际使用验证是否减少重复录入，而不是仅统计新增了多少功能。
